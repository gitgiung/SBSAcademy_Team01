# 적 생성 및 플레이어 추적 MVP

## 확정 범위

- 사용자 요구: 탑다운, 장애물 없는 공간에서 적 생성 및 플레이어 추적만 구현한다.
- 보스, 공격, 체력, 피격, 사망, 길찾기, 오브젝트 풀링은 이번 단계에 포함하지 않는다.
- 현재 프로젝트에는 플레이어와 적의 C# 구현 및 프리팹이 없다. 기존 게임플레이 구조를 변경하는 대신 작은 독립 컴포넌트로 시작한다.

## 권장 구성

### EnemySpawner

- Inspector에서 적 프리팹, 플레이어 Transform, 생성 지점 목록, 생성 간격, 총 생성 수를 받는다.
- 첫 적은 활성화 후 즉시 생성하며, 나머지는 지정 간격으로 생성한다. 총 생성 수에 도달하면 끝낸다.
- 생성 지점은 목록 순서대로 순환한다. 목록이 비어 있으면 스포너 위치를 사용한다.
- 생성 직후 적에게 추적 대상을 전달한다. 적마다 태그 검색이나 전역 객체 검색을 수행하지 않는다.
- 필수 참조가 없거나 프리팹에 추적 컴포넌트가 없으면 경고 후 생성을 중단한다.
- 스포너 비활성화 시 추가 생성을 중단한다. 재활성화해도 이미 생성한 수는 유지한다.
- 생성 수는 해당 스포너가 생성한 누적 수다. 살아 있는 적 수를 관리하지 않는다.

### EnemyFollow

- 위치: `Assets/0.Scripts/Enemy/NormalEnemy/EnemyFollow.cs`.
- Inspector에서 이동 속도와 정지 거리를 설정한다. 외부에서 추적 대상을 전달할 수 있다.
- 중력이 없는 Kinematic Rigidbody2D로 FixedUpdate에서 XY 평면을 이동한다.
- 매 이동 시 현재 플레이어 위치를 기준으로 방향을 갱신한다.
- 남은 거리와 정지 거리를 고려해 이동량을 제한하고, 목표를 지나쳐 왕복하지 않도록 한다.
- 대상이 없거나 비활성 상태면 이동을 멈춘다. 대상을 다시 지정하면 추적을 재개한다.
- 회전, Z축 이동, 적 간 회피와 밀어내기는 구현하지 않는다.
- EnemySpawner도 같은 `NormalEnemy` 폴더에 둔다. 별도 매니저나 패키지는 추가하지 않는다.

## 테스트 진입점

- 기존 팀원 테스트 씬은 수정하지 않는다.
- 별도 테스트 씬에 카메라, 눈에 보이는 플레이어 표식, 적 프리팹, 생성 지점과 스포너를 구성한다.
- 플레이어 표식은 실행 중 Scene 뷰에서 위치를 바꾸어 추적 갱신을 확인한다. 플레이어 입력·이동 시스템은 이번 범위에 추가하지 않는다.
- Inspector 연결과 재현 절차를 간단한 사용 문서로 제공한다.

## 완료 및 검증 기준

1. 설정된 위치·간격·총 생성 수에 맞게 적이 생성된다.
2. 생성된 적이 플레이어를 향해 이동하고, 플레이어 위치가 바뀌면 방향을 갱신한다.
3. 정지 거리에서 멈추고 플레이어가 멀어지면 추적을 재개한다.
4. 대상이 사라지거나 필수 참조가 누락돼도 반복 예외가 발생하지 않는다.
5. 스포너를 끄면 생성이 멈추고, 다시 켜도 총 생성 수를 초과하지 않는다.
6. 가능한 환경에서 Unity 컴파일과 관련 테스트를 실행한다. 에디터 실행 검증이 불가능하면 수행한 검사와 미검증 항목을 구분해 보고한다.

## 설계 선택

직접 Transform 이동보다 Rigidbody2D 기반 이동을 선택해 향후 2D 충돌 연동에 대비한다. 경로 탐색이나 범용 AI 프레임워크는 현재 장애물 없는 공간의 요구에 필요하지 않다. 생성 설정은 재사용 가능한 프리팹 및 Inspector 필드로 충분하며 별도 설정 데이터 계층은 만들지 않는다.
