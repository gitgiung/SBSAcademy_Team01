# 보스 6회 등장 일정 설계

상태: 사용자 설계 승인 및 구현 완료(2026-11-11). 분리 Unity PlayMode 25/25 통과, 실제 MainScene 화면 확인은 남아 있다.

## 목적과 승인된 방향

진행 타이머 3·6·9·12·15·18분에 각각 지정한 보스를 등장시킨다. 기존 BossEncounterController를 확장하고, 등장 일정은 별도 데이터로 분리한다. 보스가 없는 회차는 미지정으로 남기며 새 보스나 수치, 보상을 만들지 않는다.

## 검토한 방법

- Controller 내부 목록만 사용: 변경은 작지만 씬 사이에서 일정 공유가 어렵다.
- EnemySpawnDirector에 통합: 설정은 모이지만 일반 스폰 담당이 보스 연출·HP바·처치 흐름까지 소유하게 된다.
- 선택한 방식: Controller와 일정 데이터 분리. 기존 역할을 유지하고 Inspector에서 회차별 보스를 교체할 수 있다.

## 구성

- BossEncounterSchedule ScriptableObject에 등장 시각(초)과 보스 프리팹 목록을 저장한다. 기본 6개 시각은 180, 360, 540, 720, 900, 1080이다. 시각은 편집 가능하며 양수·오름차순을 검증한다.
- BossEncounterController는 다음 회차, 현재 생성한 보스, 처치 이벤트 구독과 HP바를 관리한다. 각 회차는 새 인스턴스로 생성해 이전 보스의 체력·패턴 상태를 재사용하지 않는다.
- EnemySpawnDirector는 기존 단일 시계, 경계 정지, 일반 스폰 역할을 유지한다. 별도 전역 매니저나 시계를 추가하지 않는다.
- 보스 프리팹은 루트 EnemyHealth와 현재 지원 보스 컴포넌트 중 하나를 갖도록 검증한다. 보스별 참조 필드를 계속 추가하지 않는다.
- 기존 HP바를 현재 보스의 EnemyHealth에 연결하는 최소 API를 보완한다. 야수의 QueueEntrance와 등장 후 HP바 페이드는 유지한다.

## 전투 흐름

1. 다음 유효 회차 시각을 Director의 정지 경계로 설정한다.
2. 경계 도달 시 지정 보스를 준비하고 일반 스폰·진행 시계를 멈춘다. 일반 적은 기존처럼 보상 없이 정리한다.
3. 기존 anchor 기준으로 배치하고 보스별 등장 처리 후 전투한다. Time.timeScale은 변경하지 않는다.
4. 현재 보스 처치 이벤트만 한 번 처리한다. HP바를 숨기고 구독을 해제한 뒤 다음 경계를 예약하고 진행을 재개한다.
5. 18분 경계에서도 마지막 보스가 등장해야 한다. 현재 Director는 정확히 Duration에 TimeAdvanced를 알리므로 이 경계를 회귀 검증한다.

## 제안하는 미지정·종료 동작

- 미지정 회차는 시작 시 회차·시각을 포함한 경고를 표시하고 건너뛴다. 다른 보스로 대체하거나 그 시각에 진행을 영구 정지하지 않는다. 프리팹 구성 오류도 구체적인 오류를 표시하고 해당 회차를 실행하지 않는다.
- 처음 제공하는 일정은 3분에 기존 야수 프리팹을 연결하고 나머지 5개는 미지정으로 둔다. 다른 보스의 순서는 임의 확정하지 않는다.
- 여섯 번째 보스 처치는 일정 종료로만 처리한다. 자동 승리, 보상, 히든 보스는 추가하지 않는다. 진행 시간·일반 스폰은 기존 18분 한도를 유지한다.

## 기존 씬 보존

- 일정이 지정되지 않은 기존 씬은 현재 boss/hordeLord/zombieSlime 및 bossAppearTime 단일 등장 경로를 유지한다. 기존 공개 API와 직렬화 필드를 보존한다.
- MainScene에만 일정 에셋을 최소 YAML 변경으로 연결한다. 기존 야수 씬 인스턴스는 비활성 대기로 유지하여 중복 등장하지 않게 한다. 사용자 씬을 에디터로 일괄 재저장하지 않는다.
- 신규 생성 보스는 기존 anchor에 배치하고, 야수의 기존 상대 위치를 보존할 수 있도록 일정에 생성 오프셋을 둔다. 기존 씬 배치는 변경하지 않는다.

## 검증과 사용자 확인

- 경계 직전/도달, 프레임 지연, 6회 순서와 서로 다른 프리팹 선택, 처치 후 다음 경계, 중복 사망 이벤트, 미지정 회차, 1080초 마지막 등장, 기존 단일 보스 경로를 회귀 검증한다.
- 가능한 C# 컴파일과 Unity 테스트를 수행한다. 원본과 같은 프로젝트의 두 번째 Editor는 열지 않는다. 실행 불가 검증은 구분해 보고한다.
- MainScene → Boss Encounter → Schedule에서 6개 시각과 프리팹을 확인한다. Play 중 Director의 기존 '테스트/진행시간 30초 앞으로'로 경계까지 진행해 등장·시계 정지·HP바·처치 후 재개를 확인한다.
- 이상 시 Console 첫 오류, 일정의 회차·프리팹·EnemyHealth, Spawn Director와 Boss Spawn Anchor 및 HP바 참조를 확인한다. 실제 Unity 화면·번들·Android 검증을 실행하지 않았다면 완료로 보고하지 않는다.
