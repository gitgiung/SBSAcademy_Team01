# 플레이어 스킬 구현 설계 초안

## 목적과 상태

Zomso_Skill_기획서.docx와 2026-11-03 사용자 결정을 현재 Player 구조에 연결한다. 이 문서는 구현 전 검토용 초안이며 런타임 구현 완료를 의미하지 않는다. 원본 기획서의 과거 자원 명칭은 MP로 해석한다.

현재 구현 상태: 1단계 탄환 풀링은 사용자 직접 확인 완료. 2단계 MP·행동 제어 기반은 구현 및 테스트 완료이며 실제 약공격 버튼/애니메이션·타격·장착과 MP HUD 표시는 다음 연결 작업이다. 구체적 검증 결과는 docs/AI/Handoff.md의 최신 항목을 따른다.

후속 구현: HP·MP·EXP HUD 연결과 선택된 HP Slider 좌우 입력 버그 수정 완료. 3단계 중 보유/장착 모델 및 참고 이미지 기반 일시정지 상태창·승인된 음량 옵션 완료. 실제 패시브/액티브 스킬 실행과 약공격 애니메이션·타격은 아직 미연결이다. SkillDatatable.xlsx/Strengthentable.xlsx가 현재 존재하며 이름/일부 분류는 작성되어 있으나 전투 실행 수치/리소스 대부분은 비어 있다. 아래 초기 코드 조사와 미발견 기록은 당시 상태이며 현재 우선순위는 Handoff 최신 항목을 따른다.

## 확정된 동작

- 자동 탄환은 발사할 때 화면 내 일반 몬스터·엘리트·보스 중 가장 가까운 유효 대상을 선택한다. 발사 순간 위치로 방향을 한 번 계산하고 직진한다. 비행 중 유도·재타겟하지 않는다.
- 다음 발사 때는 가까운 적을 다시 선택한다. 표적 사망이나 풀 반환으로 이미 발사한 직선탄의 수명을 끝내지 않는다. 적 위치에 도달했다는 거리 검사도 실제 충돌을 대신하지 않는다.
- 차징 및 패링/가드 모션 중에는 자동 발사를 중단한다.
- 약공격은 별도 쿨타임 없이 애니메이션 시작부터 종료까지 이동·공격·전략·방어·회피 입력을 차단한다. 이 시간에는 일반적인 방어/회피 우선순위보다 약공격 잠금 규칙이 우선한다. 사망·비활성화 같은 강제 종료는 잠금을 정리한다.
- 잠금 중 입력은 예약하지 않고 버리는 방식을 제안한다. 이동은 잠금 해제 후 현재 조이스틱 방향을 다시 읽는다. 홀드 중이던 버튼의 처리까지는 검증 시 명시적으로 확인한다.
- 강공격은 차징 시작 시 MP를 차감한다. 차징 배율은 누적 증가하며 단계별 시간·증가량·최대 차징 시간은 테스트 후 수정할 수 있는 데이터로 둔다.
- 전략 스킬 쿨타임 초기 기준은 6초다. 사용 횟수 및 최대 차징 시간은 테스트 후 변경 가능하다.
- 보유 스킬 슬롯은 총 8개이며 기본 6개 활성, 2개 잠금이다. 유물·증강으로 추가 슬롯을 해금할 수 있다.
- 보유 스킬은 패시브 공격으로 발사되며, 하나의 액티브 버튼에는 하나의 보유 스킬을 연결해 해당 스킬의 액티브 동작을 실행한다.
- 보스 그로기 조건과 수치는 미정이므로 구현 범위에 포함하지 않는다.

## 현재 코드와 보완 범위

- Player.cs는 입력과 구성 연결을 소유한다. PlayerCombat, PlayerMovement, PlayerDefense, PlayerView 분리를 유지한다.
- PlayerCombat.FireAt은 Object.Instantiate를 사용한다. Bullet은 target 생존 여부와 거리를 검사하고 Destroy를 호출하므로 확정된 직선탄 수명과 풀링에 맞게 바꿔야 한다.
- PlayerData는 HP와 기본 공격 수치 중심이며 MP 상태와 자원 연산을 추가해야 한다. 기존 직렬화 필드·공개 API는 보존한다.
- Data.SkillData는 예제 스키마다. 기존 로딩 계약을 유지하면서 스킬 정의를 확장하거나 호환 변환을 제공해야 한다.
- Managers.Pool 및 ResourceManager의 로딩·풀 생성 경로를 재사용한다. 전역 스킬 매니저나 별도 풀 프레임워크는 추가하지 않는다.
- SkillDatatable.xlsx는 저장소 파일 검색에서 발견하지 못했다. 실제 개별 스킬 효과·계수 전체를 임의로 생성하지 않는다.

## 구현 방식 비교와 권장안

1. 스킬별 MonoBehaviour에 비용·입력·차징·효과를 모두 넣으면 시작은 빠르지만 입력 잠금·MP 차감·취소 처리가 스킬마다 달라진다.
2. 플레이어 단위 실행부에서 공통 규칙을 처리하고, 스킬 정의와 효과 실행을 분리하면 패시브·액티브 조합과 슬롯 해금을 같은 규칙으로 다룰 수 있다.

두 번째를 권장한다. 이는 구현 제안이며 구체적 클래스명·공개 인터페이스 확정은 후속 구현 계획에서 수행한다.

## 책임 배치

| 위치 | 책임 |
|---|---|
| PlayerData | 현재·최대 MP, 유효한 비용 차감, 회복, 변경 알림 |
| Player 입력 연결 | PC/모바일 입력 수집, 입력 잠금 선검사, 동작 시작 순서 |
| 플레이어 소유 행동 조정 | 약공격 잠금, 차징/시전/후딜 상태, 취소와 강제 정리 |
| 플레이어 소유 스킬 보유 정보 | 8개 슬롯·활성 개수·해금, 버튼별 스킬 참조 |
| 플레이어 소유 스킬 실행 상태 | 패시브 발사 주기, 차징 단계, 전략 쿨타임·횟수 |
| 스킬 정의 데이터 | 패시브/액티브 정의, 비용·계수·범위·리소스 키·조정값 |
| 기존 PlayerCombat/Bullet | 발사 시 타깃 선정, 직선 이동, 충돌, 풀 반환 |
| 기존 PlayerView | 애니메이션·차징 표시·MP 부족 피드백 |
| 게임 진행 | 스테이지 시작·종료 신호. 전략 횟수 초기화 시점을 알림 |
| 기존 Core | 로딩·풀링·사운드 등 공통 기능 |

스킬 정의에는 남은 쿨타임이나 현재 차징 시간을 기록하지 않는다. 같은 정의를 여러 실행 상태가 공유해도 서로 영향을 주지 않게 한다.

## 중요한 실행 경계

- 입력 수집 → 약공격 잠금 검사 → 방어/회피 등 우선순위 결정 → MP 검사와 행동 시작 → 자동 발사 순서로 처리한다. 방어 시작 프레임의 자동 발사도 차단한다.
- 약공격 시작 시 이동 입력만 무시하지 말고 외부 모바일 조이스틱 이동 경로도 같은 잠금을 적용한다. 기존 이동 관성·진행 중 이동 처리를 확인해 잠금 중 위치 변화가 남지 않도록 한다.
- 애니메이션 종료 신호를 실행 상태와 연결한다. 이전 동작의 늦은 종료 신호가 새로운 동작 잠금을 해제하지 않도록 실행 식별자를 둔다. 비활성화·사망·강제 전환은 종료 신호 없이도 정리한다.
- 탄환은 풀 활성화 전에 방향·피해·속도·남은 수명·적중 상태를 초기화한다. 예약 Destroy는 제거한다. 대여 대상 참조를 계속 보관해 적 풀 재사용의 영향을 받지 않게 한다.
- 스킬 공격은 대상의 Collider 수가 아니라 피해 수신 대상 기준으로 중복을 제어한다. 지속/다단 공격은 해당 효과에 정의된 타격 주기를 사용한다.
- MP 부족이나 차단된 입력에는 피해·프리팹 생성·횟수 차감이 일어나지 않는다. 데이터/리소스 오류로 시작 실패한 행동의 비용 처리도 공통 시작 경로에서 일관되게 다룬다.
- 팝업 정지 중에는 MP 회복·차징·쿨타임·탄환 수명을 전투 시간과 함께 멈추는 방식을 제안한다. Hit-stop을 구현할 때 기존 팝업의 timeScale 소유권을 덮어쓰지 않는다. 보스 등장으로 진행 타이머만 멈추는 것과 구분한다.

## 구현 순서와 검증 결과물

1. 탄환 정합성과 풀링: 발사 순간 위치로 직진, 다음 발사 재선정, 표적 사망 후 비행 지속, 중복 반환 방지, 재대여 시 적중·수명 초기화를 검증한다.
2. MP와 행동 제어: 부족 시 무소모·미발동, 정상 차감·회복, 약공격 잠금 중 이동·전략·방어·회피 차단, 정상/강제 종료 후 잠금 해제를 검증한다. MP 수치가 미정이면 실제 게임 확정값으로 저장하지 않는다.
3. 보유/장착 모델과 약공격: 6개 활성·2개 잠금, 잠긴 슬롯 장착 거부, 버튼당 한 스킬 참조, 패시브와 액티브 실행 상태 분리를 검증한다. 실제 테이블이 없으면 전체 스킬을 채우지 말고 명시적 테스트 픽스처만 사용한다.
4. 강공격: 시작 시 한 번만 MP 차감, 데이터 기반 누적 배율, 방어/회피 취소, 피격·슈퍼아머, 일시정지 중 단계 유지와 표시 정리를 검증한다.
5. 전략 및 성장 연결: 6초 쿨타임, 횟수 제한·초기화, 효과 적용, 슬롯 해금 및 장착된 스킬 제거 시 참조 정리를 검증한다.
6. 연출·회귀: 차징 표시·사운드·HP 바·역경직·햅틱을 연결하고 기존 플레이어 방어·이동·팝업·풀 테스트를 다시 실행한다. Android 햅틱·성능은 실제 기기 검증으로 남긴다.

## 남은 기획 경계

- 약공격 잠금 중 자동 패시브 발사까지 중단할지 여부는 명시되지 않았다. 입력 잠금과 자동 발사 금지를 같은 것으로 취급하지 않는다.
- 각 스킬의 패시브 주기와 액티브 종류별 버튼 장착 가능 범위, 중립 조준 보정 우선순위, 강공격 취소별 MP 환불 정책은 추가 확인이 필요하다.
- 보스 그로기·미작성 효과·유물 해금 조건·성장 보상은 임의 확정하지 않는다.

## 직접 확인 절차

구현 후 MainTestScene에서 Play → 가까운 적을 바꾸며 탄환 직진/다음 발사 대상 확인 → 약공격 중 조이스틱·방어·회피·다른 스킬 입력 차단 확인 → 애니메이션 종료 후 조작 복구 확인 → MP 부족·차징 취소·전략 횟수 확인 → 일시정지·복귀·사망·재시작 순서로 확인한다.

오류가 나면 Console의 컴파일/데이터/리소스 오류, Player의 입력·스킬·프리팹 참조, 애니메이션 종료 연결, 외부 조이스틱의 잠금 적용 여부를 확인한다. 현재는 설계 문서만 작성했으며 이 확인 절차를 통과했다고 주장하지 않는다.
