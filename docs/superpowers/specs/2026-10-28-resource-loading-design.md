# 리소스 로딩 중복·동시 요청 처리

기존에 승인된 매니저 개선의 2단계다. 기존 Managers와 ResourceManager 구조를 유지하고 기존 LoadAllAsync 2인자 호출을 보존한다. 새 매니저나 패키지를 추가하지 않는다.

## 설계

- PreloadAsync와 LoadAllAsync를 하나의 콜백 기반 처리 경로로 통합한다. 코루틴은 이 경로의 완료를 기다리는 어댑터로 둔다. 별도의 두 로딩 구현을 유지하는 대안은 캐시/오류/해제 계약이 중복되므로 사용하지 않는다.
- 같은 주소와 같은 실제 위치의 동시 요청은 하나의 진행 중 에셋 로딩을 공유한다. 파일, 공급자, 타입 및 의존 리소스가 달라지면 서로 다른 위치로 판단한다. 서로 다른 위치가 같은 주소를 쓰거나 요청 타입이 맞지 않으면 명시적으로 실패한다.
- 라벨 조회 핸들은 배치마다 자신이 취득한 참조를 정확히 한 번 해제한다. 에셋 핸들은 진행 중 요청 하나가 소유하다가 성공 시 캐시로 이전한다.
- LoadAllAsync<T>(string, Action<string,int,int>)는 유지한다. 성공/실패를 받는 3인자 overload Action<bool,string>을 추가한다. 기존 2인자 호출의 실패는 Console에 보고한다.
- 진행 콜백은 처리된 에셋 수를 전달하고, 전체 성공 여부는 완료 콜백으로 판단한다. 빈 라벨/조회 결과는 진행(null,0,0) 후 실패 완료한다.
- 실패한 결과는 캐시하지 않아 재시도가 가능하다. 캐시에서 반환해도 각 요청은 자신의 진행/완료 콜백을 받는다.
- Clear는 현재 배치와 진행 중/캐시 핸들을 먼저 분리하고 준비 세대를 변경한다. 취소된 요청은 실패로 종료하며 늦게 끝난 이전 작업이 새 캐시를 채우지 못한다. 정리 콜백에서 새 요청을 시작해도 새 요청은 유지한다.
- 한 호출자의 콜백 예외가 다른 호출자의 알림이나 핸들 정리를 막지 않는다.
- 같은 주소의 Sprite와 원본 Texture는 기존대로 Sprite를 우선하며, 다른 모호한 주소 충돌은 실패한다.

## 검증 및 범위

Unity 6000.5.0f1 / Addressables 2.9.1을 유지한다. 기존 21개 테스트를 보존하고 중복 요청, 두 API 혼용, 빈 라벨, 실패 후 재시도, Clear 도중 완료, 캐시 재사용, 콜백 예외를 실제 Addressables 메모리 공급자로 검증한다. 에디터가 열려 있어 별도 검증 복사본에서 실행한다. Windows 긴 경로 제한을 피하기 위해 임시 디렉터리를 사용하고 위치는 .utmp/ResourceLoading/validation-path.txt에 기록한다. 검증 복사본에서만 PlayFromTitle의 배치 실행을 우회하며 사용자 EditorPrefs와 원본 편집기 코드는 바꾸지 않는다. 사용자 씬과 프로젝트 설정은 수정하지 않는다. UI·사운드의 추가 기능과 Android 검증은 이번 단계에 포함하지 않는다.
