# 18분 생존·성장 밸런스 구현 명세서 (Codex용)

버전: v0.1  |  작성일: 2026-11-04  |  상태: 1차 플레이테스트용 임시 밸런스

목표: Unity 프로젝트에 18분/100레벨/동시 일반 몬스터 130마리 제한을 적용하고, 30초별 스폰 및 경험치·레벨 성장과 3분별 성장 보정을 기존 시스템에 통합한다.

이 문서의 숫자는 최종 확정 밸런스가 아니라 테스트용 기준값이다. 코드 구조를 직접 확인하기 전에는 기존 클래스명·경로·인터페이스를 가정하지 않는다.

## 0. Codex에 전달할 최상위 작업 지시

아래를 Codex의 실행 지침으로 사용한다.

1. 프로젝트를 먼저 탐색해 GameManager/Managers, PoolManager, Enemy/Death, EnemySpawner, PlayerModel/Level/Experience, 경험치 드롭/획득과 타이머의 실제 구조 및 호출 경로를 확인한다.

2. 기존 기능이 존재하면 확장하며, 동등한 Manager나 Pool 시스템을 중복 생성하지 않는다. 데이터와 런타임 상태는 분리한다. 사용 중인 Unity 버전 및 프로젝트 코드 스타일을 따른다.

3. 이 명세의 구현 범위를 작은 단계로 나누어 반영한다. 성능 우선: 대량 생성 경로에서 반복 Instantiate/Destroy 및 프레임마다 전체 적 탐색을 피한다.

4. 수치 검증 테스트를 작성하고 가능한 테스트를 실행한다. 수정한 파일별 변경 이유, 기존 시스템과의 연결 방식, 남은 위험과 플레이테스트 항목을 보고한다.

5. 기존 프로젝트의 무관한 코드나 에셋을 광범위하게 수정하지 않는다. Git 커밋·PR은 별도 요청이 없으면 수행하지 않는다.

## 2. 레벨별 필요 경험치

현재 레벨 L(1~99)에서 다음 레벨로 올라가는 요구 경험치는 아래와 같이 반올림한다. 소수점 .5는 올림(half-up)한다.

```csharp
RequiredXP(L) = RoundHalfUp(0.9 × (12 + 2.2×L + 0.075×L×L))

// 부동소수점 오차를 피하는 동등한 정수 연산 예시
int RequiredXP(int level)
{
    if (level < 1 || level >= 100) return 0;
    int numerator = 108000 + 19800 * level + 675 * level * level;
    return (numerator + 5000) / 10000;
}
```

| 1 | 13 |
| 10 | 37 |
| 20 | 77 |
| 30 | 131 |
| 40 | 198 |
| 50 | 279 |
| 60 | 373 |
| 70 | 480 |
| 80 | 601 |
| 90 | 736 |
| 99 | 868 |

- 레벨업 시 현재 보유 경험치에서 해당 레벨 요구량을 차감하고 레벨 +1. 한 번에 다량의 XP를 얻어도 while 방식 등으로 여러 레벨업을 처리한다.

- 100레벨에 도달하면 추가 레벨업이 발생하지 않는다. 기존 게임에 최대 레벨 보상 또는 잔여 XP 표시 규칙이 있으면 그 방식을 우선 보존한다.

- 검증 기준: Sum(RequiredXP(1..99)) = 33,033 XP. 기존 공식(36,703 XP)은 더 이상 적용하지 않는다.

## 4. 일반 몬스터 생성과 130마리 제한

- 월드의 활성 일반 몬스터 수(activeNormalEnemyCount)를 이벤트 기반으로 유지한다. 스폰 성공 시 +1, 사망·씬 정리·거리 이탈로 풀에 정상 반환될 때 단 한 번 -1 한다.

- 스폰 요청 시 130마리 이상이면 해당 시도를 건너뛴다. 막힌 스폰을 무한 대기열에 쌓거나 이후에 한꺼번에 보충 생성하지 않는다.

- 0번 웨이브는 30초 동안 50회를 목표로 일정하게 시도(평균 0.6초마다), 35번 웨이브는 400회 시도(평균 0.075초마다). 프레임 단위 누산기 또는 시간 기반 스케줄러를 사용하되 프레임 급증 시 일괄 폭발 생성은 제한한다.

- Boss/특수 소환 등은 기존 정책을 유지하고 130마리 일반 몬스터 한도를 임의로 적용하지 않는다. 풀의 inactive 오브젝트 수는 130 상한에 포함하지 않는다.

- 게임 시간 18분 종료 시 일반 스폰만 중단한다. 게임 종료/보스전 전환 흐름은 기존 구현을 존중하고 새로 설계하지 않는다.

- 스폰 실패(130 상한, 풀 확보 실패 등)는 실제 생성 성공 수와 분리하여 집계한다. “스폰 목표 8,100”과 “실제 스폰 8,100”을 혼동하지 않는다.

예시: 마지막 웨이브 목표는 30초에 400마리지만, 평균 생존 12초면 단순 근사 활성 수가 160마리로 130마리 상한에 걸린다. 따라서 실제 처치 능력·몬스터 HP·풀 반환 정책이 레벨 도달 시점에 영향을 준다.

## 5. 사망 → 경험치 드롭 → 경험치 회수 → 레벨업

1. 일반 몬스터의 실제 처치가 확정되면 한 번만 처치 XP 보상을 발생시킨다(기본 100% 지급). 적 종류별 XP가 이미 있으면 현 구조를 보존하되, 1차 테스트에서는 위 구간의 기준 XP가 되도록 데이터와 연계한다.

2. XP 보석/오브젝트 획득 방식이 이미 있으면 해당 파이프라인을 이용한다. 없다면 PoolManager를 통한 경험치 픽업의 최소 구현을 추가한다. 오브젝트를 매 처치마다 Instantiate/Destroy하지 않는다.

3. 경험치 보석은 원래 지급 XP(rawXP)를 보유한다. 플레이어가 실제 획득한 시점에만 Player 경험치에 반영한다. 거리 이탈 또는 미획득 보석은 실제 획득 XP에 포함하지 않는다.

4. 레벨업 이벤트/스킬 선택/플레이어 UI가 이미 연결되어 있다면 기존 이벤트를 그대로 호출한다. 새로운 UI 흐름을 중복 생성하지 않는다.

5. 보정 배율이 적용될 때 정수 XP 손실을 피하려면 획득마다 소수 잔여분을 누적한다. 예: 2 XP × 1.25를 두 번 획득 → 합계 5 XP. 단건 각각을 3 XP로 반올림해 6 XP로 만드는 방식은 피한다.

```text
awardedExact = rawXP * (catchupActive ? 1.25 : 1.0) + fractionalCarry;
awardedInt = FloorToInt(awardedExact);
fractionalCarry = awardedExact - awardedInt;
AddExperience(awardedInt);
```

중복 사망 콜백, 중복 Trigger, 사망과 거리 이탈의 중복 반환을 막아야 한다. 기존 PoolManager/ResourceManager/Enemy의 관리 주체를 분석하고 하나의 반환 흐름으로 통일한다.

## 6. 100레벨 달성형 경험치 보정

3, 6, 9, 12, 15분에 목표 레벨을 확인한다. 이는 1차 테스트를 위해 “일정 수준 이상 낮다”를 수치화한 초기 기본값이며 플레이테스트 후 변경 가능한 설정이어야 한다.

| 게임 시간 | 목표 레벨 |
| --- | --- |
| 03:00 | 19 |
| 06:00 | 35 |
| 09:00 | 51 |
| 12:00 | 70 |
| 15:00 | 87 |

- 체크포인트 시 목표 Lv − 현재 Lv ≥ 3이면 catchupActive = true(획득 경험치 +25%).

- 목표 Lv − 현재 Lv ≤ 1이면 catchupActive = false(경험치 보정 종료).

- 차이가 2레벨이면 현재 보정 상태를 유지한다(켜짐/꺼짐 히스테리시스).

- 보정 여부는 해당 체크포인트 이후 획득한 XP에만 적용한다. 이미 획득한 경험치, 맵에 떨어져 있는 보석의 원래 rawXP, 몬스터의 보상 수치는 소급 변경하지 않는다.

- 100레벨이면 보정 종료. UI에 보정 사실을 노출할 필요는 없고 디버그 로그/지표로 확인 가능하도록 한다.

- 15분 이후 추가 경험치 아이템/즉시 지급 보상은 아이디어 단계이므로 v0.1에는 구현하지 않는다.

예시 검산: 초보자 처치율 70%·회수율 85%를 매 구간에 일정하게 적용하면 보정이 없는 경우 18분에 약 30,149 XP. 위 3분 체크포인트 보정(3레벨 부족 시 ON/1레벨 이내 OFF) 모델은 수학적 집계상 약 36,856 XP까지 회복할 수 있다. 이는 목표 스폰이 모두 달성된다는 이상화 가정이며 게임 내 100레벨을 보증하는 수치가 아니다.

| 성장 보정 | 3분 체크포인트 비교, 보정 상태 유지 | 설정 데이터로 임계값 교체 가능 |
| 디버그 지표 | 30초 샘플링 및 테스트 출력 | Release 기본 비활성 권장 |

설정 데이터는 기존 ScriptableObject 또는 데이터 테이블 방식에 맞춘다. 경험치 공식, 36구간 스폰 목표(또는 시작값/증가값), 6개 XP 단계, 보정 체크포인트/임계값/배율, 몬스터 상한을 에디터에서 조정 가능하도록 한다. 런타임 카운트·현재 레벨·잔여 소수는 ScriptableObject 에셋에 직접 저장하지 않는다.

## 8. 기능 검증 및 완료 조건 (Acceptance Criteria)

- 수치: Lv1→100 누적 필요 XP = 33,033; Lv100 이상 추가 레벨업 없음; 다량 XP 한 번 수령 시 중간 레벨이 누락되지 않음.

- 시간: 0~29.999초 index=0, 30초 index=1, 179.999초 XP=2, 180초 XP=3, 1,080초 일반 스폰 중단.

- 스폰: index 0 목표 50, index 35 목표 400, 36구간 목표 총합 8,100. 활성 일반 몬스터는 어떠한 프레임에서도 130을 넘지 않음.

- 풀: 몬스터 처치/거리 반환/씬 정리 각각 정상 카운트 복구, 중복 반환 없음. 풀 부족/상한 초과 시 프레임 급증이나 무한 보충 큐 없음.

- 경험치: 몬스터 처치 1회당 1회 지급, 거리 반환은 미지급; 중복 픽업은 1회만 처리; 보석 미회수는 플레이어 XP에 미반영.

- 보정: 3/6/9/12/15분 체크, 목표 대비 3레벨 이상 뒤처지면 ON, 1레벨 이내면 OFF, 2레벨 차이면 상태 유지.

- 소수: XP 2짜리 2회 획득 시 보정 25% 적용 총합은 정확히 5 XP; 보정 해제 후 잔여분을 버리지 않음.

- 통합: 기존 PlayerModel, XP/UI 및 Managers/PoolManager 흐름을 깨지 않음. 일시정지·레벨업 선택 중에는 프로젝트의 게임 시간 규칙을 준수.

- 측정: 각 30초 구간마다 목표 시도 수 / 실제 생성 수 / cap 스킵 수 / 처치 수 / XP 드롭 및 회수량 / 현재 레벨 / 최고 활성 몬스터 수 / 보정 상태를 확인 가능.

## 9. 플레이테스트 기록 및 추가 결정 보류

플레이테스트에서는 아래 값을 30초 간격으로 기록한다. 데이터로 보정 여부 및 수치(최대 활성 수, 스폰, 적 HP, 드롭 XP)를 조정하되 v0.1 코드는 매직 넘버 없이 설정 중심으로 유지한다.

```text
elapsedSec,waveIndex,spawnTarget,spawnSuccess,capSkipped,activeNormal,peakActiveNormal,normalKills,xpDropped,xpCollected,playerLevel,catchupActive
```

테스트 우선순위: (1) 130마리 제한에 얼마나 자주 걸리는지 → (2) 실제 처치율/보석 회수율 → (3) 3·6·9·12·15분 실측 Lv → (4) 100레벨 도달 시간 → (5) 기기별 성능(FPS/GC Alloc).

v0.1 범위 밖: 몬스터 체력·DPS 상세 수치, 보스전 설계, 100레벨 이후 보상, 추가 경험치 보너스 아이템, 고급 XP 보석 병합 정책, 저장/로드 확장, UI 디자인 변경. 기존 기능이 있다면 파괴하지 말고 유지한다.
