# 맵 개발 지시서 (뱀서류 무한 맵)

작성: 2026-11-04. 상태: 지시·합의용. 구현 착수 전 문서. 수치·스테이지 크기·청크 크기는 미정으로 남긴다.

## 1. 목적

- 플레이어가 맵 끝에서 막히지 않고, 바닥이 이어져 **끝없이 달린 느낌**을 주는 맵을 만든다.
- 뱀서(Vampire Survivors류)에서 흔히 쓰는 방식에 맞춘다.
- 기존 `WorldWrap2D`의 **전체 타일맵 8장 복제 + 플레이어 반대편 순간이동**은 정식 목표 기법이 아니다. 프로토타입·임시 확인용으로만 취급한다.

## 2. 한눈에 보는 비교

| 구분 | 지금 (`WorldWrap2D`) | 이 지시서의 목표 (뱀서식) |
|---|---|---|
| 플레이어 | 경계 밖이면 **반대편으로 텔레포트** | **계속 같은 방향으로 이동** (좌표를 접지 않음) |
| 바닥 | 큰 Ground 타일맵을 **주변 8칸에 통째 복제** | **작은 청크**만 플레이어·카메라 주변에 두고 **멀어진 조각을 앞으로 재사용** |
| 월드 느낌 | 같은 맵이 둥글게 이어진 루프 | 보이기만 무한처럼 이어지는 **청크 스트림** |
| 부하 | 큰 타일맵 × 8 → 로드·리스타트에 무거움 | 청크 수 고정, 위치만 옮김 → 가벼움 |
| 적·드랍 | 래핑 대상이 아님 (미구현) | 플레이어 기준 스폰·화면 밖 배치와 맞출 것 |

결론: **목표는 “무한 맵 느낌”, 구현은 “청크 재배치”다. “전체 맵 복제 + 래핑”이 아니다.**

## 3. 현재 코드 위치 (참고만)

- 스크립트: `Assets/0.Scripts/Game/WorldWrap2D.cs`
- 연결 씬: `Assets/9.Scenes/MainTestScene.unity` → `Player Target`의 `WorldWrap2D`
- 원본 바닥: 씬의 `Ground` Grid + `Tilemap` (칸 수가 많으면 복제 비용이 커진다)
- 카메라: 플레이어 중앙 고정(Cinemachine). 맵 경계 Confiner는 후속이었고, **무한 청크 맵과는 역할이 겹치므로** 청크 방식으로 가면 경계 가두기는 쓰지 않거나 별도 합의가 필요하다.

정식 청크 맵이 들어오면 `WorldWrap2D`는 제거하거나 비활성하는 것을 기본으로 한다. 한 씬에 두 방식을 동시에 켜지 않는다.

## 4. 권장 기법 (개발이 따를 규칙)

### 4.1 청크

- 바닥은 **한 장짜리 거대 타일맵을 복제하지 않는다.**
- **청크** = 화면보다 작거나 비슷한 크기의 바닥 단위(타일맵 조각, 스프라이트 타일 세트, 프리팹 등). 구체 크기·타일 수는 **미정**.
- 동시에 살아 있는 청크 개수는 **고정 상한**을 둔다(예: 플레이어 주변 3×3). 예시는 확정 수치가 아니다.
- 플레이어가 한 청크 이상으로 이동하면, **가장 먼 청크를 진행 방향 앞쪽으로 옮겨** 다시 쓴다. 새로 Instantiate로 맵 전체를 늘리지 않는다.

### 4.2 플레이어·카메라

- 플레이어 Transform/Rigidbody 위치는 **래핑하지 않는다.** 한 방향으로 계속 누적되어도 된다.
- 카메라는 기존처럼 플레이어 중앙 추적을 유지한다.
- “무한”은 **시각·스폰 기준**으로 만들고, 플레이어를 맵 반대편으로 순간이동시켜 만들지 않는다.

### 4.3 적·경험치·투사체

- 일반 몬스터 스폰은 기존처럼 **카메라 밖·플레이어 기준**을 우선한다. (`docs/AI/EnemySpawning.md`)
- 청크가 옮겨져도 적·DNA·탄이 청크 자식이 되어 함께 끌려가지 않게 한다. 월드에 독립 배치한다.
- 일반 몬스터 동시 130마리 제한은 스폰 규칙으로 유지한다. 풀 `maxSize`와 혼동하지 않는다.
- 적·투사체까지 “맵 래핑”하는 로직은 이 지시서 범위에서 **하지 않는다.**

### 4.4 아트·타일

- 청크끼리 이어질 때 **가장자리가 자연스럽게** 맞아야 한다. 패턴이 반복되어도 이음새가 드러나면 아트/타일 배치를 고친다.
- 스테이지마다 다른 바닥 세트를 쓸지는 **미정**. 우선 MainTestScene 검증용 한 세트로 충분하다.
- 기존 `Ground` 대형 타일맵을 청크 소스로 잘라 쓸지, 새 청크 프리팹을 만들지는 구현 착수 때 정한다. 결정 전까지 씬의 대형 Ground를 8장 복제하는 방식을 확장하지 않는다.

## 5. 하지 말 것

- 원본 Ground Grid 전체를 `Instantiate`로 8방향(또는 N방향) 복제해 무한 맵을 흉내 내기
- 플레이어(또는 카메라)를 고정 Rect 반대편으로 텔레포트해 무한처럼 보이게 하기
- 청크·래핑용 **새 전역 매니저·싱글톤·이벤트 프레임워크** 추가
- 맵 때문에 전투 전체를 `Time.timeScale = 0`으로 멈추기
- 기획 미정 수치(청크 크기, 스테이지 반경, 장식 밀도, 히든 보스 맵 조건 등)를 임의 확정·하드코딩
- 씬·프리팹·meta를 지시 구현에 필요 없는 범위까지 일괄 재저장

## 6. 책임 나누기

| 담당 | 내용 |
|---|---|
| 맵/청크 컴포넌트 | 청크 풀(또는 고정 개수 오브젝트) 위치 재배치, 플레이어 기준 격자 계산 |
| 플레이어 | 이동·전투. 맵 래핑 로직을 플레이어에 넣지 않음 |
| 카메라 | 플레이어 추적만. 맵 복제·청크 이동을 카메라에 넣지 않음 |
| 스폰 | 기존 Enemy Spawn Director / Spawner. 맵 청크와 부모-자식으로 묶지 않음 |
| Core/Managers | 기존 Pool·Scene만 재사용. 맵 전용 새 Managers 하위 시스템 남설 금지 |

클래스·파일 이름, 청크를 Tilemap으로 할지 Sprite로 할지는 구현 설계 단계에서 정한다. 이 지시서는 **동작 규칙**만 고정한다.

## 7. 권장 작업 순서

1. **합의**: 이 지시서의 “청크 재배치 / 플레이어 비래핑”을 정식 방향으로 확정했는지 확인한다.
2. **프로토타입**: MainTestScene에서 작은 청크 몇 개만으로 플레이어 이동 시 재배치가 보이는지 검증한다. `WorldWrap2D`는 끈 상태로 비교한다.
3. **정리**: 검증 후 `WorldWrap2D`와 8장 복제 경로를 제거하거나 데모 전용으로 격리한다. 한 씬에 두 시스템 공존 금지.
4. **연동**: 스폰·카메라·보스전이 청크 이동과 충돌하지 않는지 확인한다.
5. **아트**: 이음새·반복 패턴을 다듬는다. 수치는 기획 합의 후.
6. **회귀**: 리스타트·Play 종료 후 청크/복제 오브젝트가 Hierarchy에 남지 않는지, Unity가 멈추지 않는지 확인한다.

## 8. 미정 (임의로 정하지 말 것)

- 청크 가로·세로 크기, 동시 청크 개수
- 스테이지별 맵 테마·장애물·파괴 가능 오브젝트 여부
- 맵 장식(나무·바위)을 청크에 넣을지, 별도 레이어로 둘지
- 보스전 중 청크 이동 동결 여부
- 미니맵·좌표 UI 표시 여부
- Android/저사양에서의 청크 상한

## 9. 직접 확인할 순서 (구현 후)

1. Unity에서 대상 씬을 연다. Console에 새 빨간 오류가 없는지 본다.
2. Play 후 한 방향으로 長く 이동한다. 플레이어가 텔레포트되지 않고, 바닥이 끊기지 않으면 정상이다.
3. Hierarchy에서 청크 개수가 상한을 넘지 않고, 멀리 간 조각이 앞쪽으로 재사용되는지 Scene 뷰로 확인한다.
4. 적이 화면 밖에서 스폰되고, 청크가 옮겨져도 적이 바닥과 같이 순간이동하지 않는지 확인한다.
5. Game Over 리스타트 또는 Play 중지 후 재실행한다. Unity가 멈추지 않고, `(Wrap …)` 같은 임시 복제물·잉여 청크가 씬에 남지 않으면 정상이다.
6. 오류 시 Console 첫 오류, 플레이어 위치, 청크 루트 오브젝트, `WorldWrap2D` 잔존 여부, 스폰 Director 참조를 순서대로 본다.
