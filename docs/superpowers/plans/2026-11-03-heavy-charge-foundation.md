# 강공격 차징 기반 구현 계획

**Goal:** 테이블 없이 차징 시작·누적 단계·해제 결과·취소를 실제 Player 입력에서 검증한다.
**Architecture:** PlayerHeavyCharge가 플레이어별 실행 상태/설정 스냅샷을, Player가 기존 MP·입력·행동 연계를, PlayerView가 조준 표시를 소유한다. 새 전역 매니저와 실제 강공격 효과/스킬 ID는 만들지 않는다.
**Spec:** 기존 player-skills-design.md 및 이번 사용자 결정. 차징 중 이동 차단/조준 변경 허용. 방어·회피·피격 취소 MP 반환 없음. 승인된 테스트 설정 MP10, 단계 시점0/.4/.8초, 누적 배율1.1/1.2/1.7(증분.1/.1/.5). Inspector에서 변경 가능.

## 경계

- 누르는 순간 비용 한 번 차감. MP 부족/약공격 잠금/방어·대시 중/잘못된 설정이면 시작 거절. 비용 알림 중 비활성화/사망/정지로 실제 시작 실패한 경우만 복구.
- 홀드 최대 단계에서 유지, 해제 시 방향/단계/배율/실행 ID 스냅샷 이벤트를 한 번 전달. 실제 피해/공격 애니메이션/그로기는 후속. 차징 중 약공격 및 자동 패시브 차단.
- 일시정지 중 시간/표시 유지. 정지 중 입력 해제·포커스 상실은 취소하여 복귀 후 공격 예약 방지. 취소 후 늦은 포인터/키 해제가 새 차징에 영향을 주지 않도록 ID로 검증.
- 피격은 기존 HP 처리 유지. SuperArmor=false면 실제 HP 감소 시 취소, true면 피해는 받되 차징 유지. 사망/비활성화는 항상 정리.
- C_Attack에 런타임 PointerDown/Up 연결. PC는 선택적 Player/HeavyAttack이 있으면 복제, 없으면 테스트 Q 입력만 생성(원본 InputAction 에셋 수정 없음).
- 기존 약공격/이동/방어/회피 API와 직렬화 참조 보존. MainTestScene에 테스트 설정과 C_Attack 참조만 추가. 다른 씬에서는 테스트 입력 기본 비활성.

## 작업

- [ ] 실패 테스트: 누적 배율, 비용1회/부족/재진입, 스냅샷, 최대 홀드/정지, 중복·늦은 해제, 취소/슈퍼아머/죽음.
- [ ] PlayerHeavyCharge와 직렬화 설정/해제 결과 구현.
- [ ] Player/모바일/버튼/View 연결. 설정 없는 씬에서 기존 동작 보존.
- [ ] 실제 Player 입력·MP·이동/조준·패시브 정지·방어/대시·생명주기 통합 검증 및 관련 회귀 실행.
- [ ] 독립 리뷰, 필요한 수정/재검증, Handoff와 직접 확인 문서 갱신. 커밋/브랜치 변경 없음.

## 검증

기존 짧은 임시 Unity 프로젝트 사용, 원본 에디터 중복 실행 금지. 실제 원본 씬/Android/정식 테이블 및 강공격 피해는 검증 범위 밖. 테스트용 설정과 최종 게임 수치를 구분한다.
