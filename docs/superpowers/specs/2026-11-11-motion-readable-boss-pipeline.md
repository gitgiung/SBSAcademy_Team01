상태: **본선 파이프라인 착수**. 검증 씬 `SoulArena3D`(병행). MainScene은 레거시 유지 후 단계 합류. 팀 안내: `docs/AI/SoulPipeline-TeamGuide.md`.

## 1. 기획 의도 (고정)

- **핵**: 모바일에서 소울류 공방. 성장 가중치는 낮고, 숙련·모션 읽기가 전면.
- **껍데기**: 뱀서(서바이버즈)는 최소화. “잡으며 큰다”는 집단 문해력만 빌려 ~3분 이완 후 보스에서 본편.
- 스토어/인게임에서 뱀서·소울을 나눠 설명하지 않는다. 플레이어는 뱀서인 줄 알다가 보스(특히 페이즈2의 한 기믹)에서 소울 수준을 뒤늦게 인지한다.
- 페이즈2는 난이도 폭증이 아니다. **한 기믹이 게임을 가르고**, 읽고 대응하면 “깨겠다”는 자신감을 주는 것이 목표.
- 성장(뱀서 구간)이 보스 숙련·기믹을 무시하게 만들면 안 된다.

### 이 프로젝트의 소울 경험

- 공격 예고의 본체는 UI / 바닥 경고 / VFX 텔레그래프가 **아니다**.
- 본체는 보스가 **다가오며 휘두르는 모션**(몸·무기 궤적)을 읽는 것이다.
- 모바일에는 **최소 UI 보조**만. 메인이 UI면 소울이 아니다.
- 현재 일부 “텔레그래프”는 모션 한계 때문에 VFX로 그려 달라 한 것이 시스템으로 굳어진 **오용**이다. 이를 의도된 소울 설계로 확장하지 않는다.
- 소울 보스 공격은 제자리 스윙이 아니라 **유저에게 접근하며 궤적이 이어진다**. 도트 시트로 거리·각도마다 장을 쪼개는 방식은 팀에서 불가능하다.

## 2. 현재 상태 진단 (짧게)

대상: MainScene Beast Zombie (`BossController` + 8방향 스프라이트 Animator).

| 패턴 | 공격 중 이동 | 예고의 실체 | 판정 |
|------|-------------|-------------|------|
| 할퀴기 (패턴1/2) | **제자리** (시작 시 추격 OFF, 방향 고정) | 스프라이트 윈드업 + **바닥 부채꼴 VFX** (`ShowSlash`) | `OverlapCircle` + 각도 내적. 손/무기 콜라이더 없음. AnimationEvent ~0.79s |
| 2페이즈 원형 | **완전 정지** | **바닥 원 예고 1.5s** (`ShowArea`) + 양손 스프라이트 | 중심 `OverlapCircle`. AnimationEvent / normalized 0.5 보조 |
| 돌진 | **접근 이동** (추적) | 돌진 자세·실제 접근. 사전 바닥 경로 없음 | 도달 시 플레이어 위치 원형. 충격 VFX는 사후 피드백 |
| 등장 | 원형 패턴 재사용 | 큰 폭발 VFX + 모습 공개. 등장 자체 피해 없음 | `ApplyAreaDamage`에 공개 시점 결합 |

플레이어: 자동 탄환 + 약공격 PNG/VFX + `Overlap*` 즉시 판정. 뼈대/무기 콜라이더 파이프라인 **없음**.  
3D/Mixamo/SkinnedMesh/휴머노이드 Avatar: 프로젝트에 **없음**. Beast Zombie는 Sprite 키 교체 2D Animator, 자식 뼈 Transform 없음.

**요약**: 할퀴기·원형은 **바닥 범위 VFX 의존도가 높다**. 돌진만 “접근 운동으로 읽기”에 가깝다. 핵 경험과 어긋난다.

## 3. 개편 방향 (범위)

### 목표 매체

- 인간형(플레이어 / 일부 몬스터 / 보스): **본(본) 모션**(Mixamo 등 활용 가능) + 손·검 등 **부위 콜라이더**.
- 판정은 모션에 붙은 부위가 움직이며 닿는 것으로 한다. 고정 부채꼴/원형 `Overlap`을 소울 공격의 본체로 두지 않는다.
- 잡몹: 뱀서형 이동 위주. 슬라임 등 단순 유지 가능. 드문 이형은 그때 전용 모션.
- 포켓봉크: **렌더/배치 방식만** 참고. 장르·시스템 이식 금지.

### 예고 계층

1. **메인**: 접근 + 휘두르기 모션(몸·무기 궤적)
2. **보조(모바일 최소)**: 짧은 UI 힌트 등. 없어도 반응 가능해야 함
3. **금지(핵으로 키우지 않음)**: 바닥 부채꼴/원형 경고를 소울 예고의 본체로 확장, VFX 텔레그래프 시스템 고도화

### Beast Zombie — **개편(B) 확정**

- 야수 좀비를 본 모션 + 부위 콜라이더 파이프라인으로 개편한다.
- 사용자는 **수정 버전을 별도 커밋해 공유**할 예정. 에이전트는 그 커밋/에셋이 오기 전에 현행 2D PNG·73클립을 대규모로 덮어쓰지 않는다.
- 개편 착수는 **한 패턴(다가오며 휘두르기)** 부터. 전 패턴·등장 연출 일괄 교체는 하지 않는다.
- 기존 2D 자산은 교체 전까지 플레이 가능 상태로 두거나, 프로토타입이 붙는 동안만 샌드박스/브랜치에서 병행한다(공유 커밋 방식에 맞춤).

### 후순위 / 비핵

- pixelfx 스킬·카드 테두리 bake: 성장/주스. 용량↑·핵 아님. 본선으로 삼지 않음. 필요 시 공용/코드/후순위만.
- 스킬마다 PNG bake 양산: 기본 금지·공용화.

## 4. 성공 기준

### 경험

- 플레이어가 경고 UI/바닥 원이 아니라 **보스의 접근·휘두르기 모션**을 보고 반응한다.
- 페이즈/기믹 하나에서 “아 이렇게 읽으면 되겠다”는 자신감이 생긴다.
- 초반 뱀서 껍데기는 유지. 본편 인식은 보스·기믹에서 온다.

### 프로토타입 합격 (최소)

- [ ] UI/바닥 예고를 **끈 상태**에서도 한 패턴의 windup→타격 궤적을 보고 회피·패링 타이밍을 잡을 수 있다.
- [ ] 공격 중 보스가 **제자리 고정이 아니라** 플레이어 쪽으로 접근하며 궤적이 이어진다.
- [ ] 피해는 손/무기(또는 동일 역할) 콜라이더 활성 구간에만 발생한다. 고정 부채꼴 `Overlap`이 본체가 아니다.
- [ ] 모바일에서 최소 UI 보조만 켜도 되고, 꺼도 플레이 가능하다(보조는 필수 아님).
- [ ] 동일 씬에서 잡몹 다수 + 해당 보스 1체가 기획 성능 한도 안에서 동작한다(수치는 아래 예산).

### 비목표 (이번 프로토타입)

- 전 보스·전 패턴 교체, 맵 전체 3D화, 포켓봉크식 시스템, pixelfx 스킬 양산, 성장 밸런스 전면 재조정.

## 5. 성능·용량 예산 (기획 한도, 합의용)

| 항목 | 한도(초안) | 비고 |
|------|------------|------|
| 정밀 부위 콜라이더·무거운 모션 | 보스·플레이어 중심 | 잡몹은 단순 몸체/접촉 위주 |
| 동시 활성 잡몹 | 기존 스폰 규칙(약 130) 유지 전제 | 풀 `maxSize` ≠ 동시 활성 한도 |
| 스킬 VFX | 가볍게, 공용화 | 스킬마다 pixelfx PNG bake 양산 금지 |
| 프로토타입 추가 용량 | 합의 전 상한 미정 | 사용자(기획)가 완성본 용량 한도 확정 |
| 서버 | **추후** | 스토어 연동·패치 편의용. 전투 동기화 본선 아님. 프로토타입·현 단계는 **로컬만** |
| 맵 | **평탄 3D** | 굴곡 없음 → 플레이 감각은 2D와 동일. 카메라/이동은 평면 전투 유지 |

구현 세부(애니 임포트, 리깅, 콜라이더 켜고 끄기 API)는 개발 2인 영역. 이 문서는 범위·성공 기준·한도만 고정한다.

## 6. 최소 검증 단위 (제안)

**한 패턴만.** 구현됨(2026-11-11):

1. 씬 `Assets/9.Scenes/MotionBossPrototype.unity` — Bootstrap이 런타임으로 임시 몸·플레이어·평탄 바닥 구성.
2. 패턴: 추격 → **다가오며** 팔 올리기(windup) → 손 트리거 활성 스윙 → 회복. 바닥 예고 없음.
3. 임시 몸: 현재 URP 2D Renderer 한계로 스프라이트 Body/Shoulder/Arm/Hand. Mixamo 교체 시 같은 계층·`MotionBossWeaponHitbox` 계약을 유지.
4. MainScene / BeastZombie 미수정. 사용자 야수 좀비 수정 커밋과 병행 가능.

합격: 바닥 경고 없이 접근+휘두르기 모션만으로 회피·패링이 가능하면 통과.

## 8. 합의 상태

| 항목 | 결정 |
|------|------|
| 야수 좀비 | **개편(B)**. 수정본은 사용자가 별도 커밋으로 공유 예정 |
| 맵 | **평탄 3D**(굴곡 없음). 2D와 플레이 차이 최소 |
| 서버 | 스토어·패치용 **추후**. 지금 전투/프로토타입은 로컬 |
| 페이즈2 한 기믹 | **기획 미정**. 파이프라인과 분리. 확정 전 구현 안 함 |
| 프로토타입용 모델 | **임시 몸 확정** (Mixamo 등 또는 동등한 임시 3D). 이후 야수 좀비 최종 모델로 교체 |

### 착수 규칙

- 임시 몸으로 “다가와서 휘두르기 + 손 판정” 1패턴만 검증.
- MainScene 야수 좀비 전면 교체·맵 전면 3D화·서버·페이즈2 기믹은 이번 범위 밖.
- 사용자가 공유할 야수 좀비 수정 커밋과 충돌하지 않게, 프로토타입은 샌드박스/별도 프리팹에 둔다.
